# 设置确认交互审计（2026-10-12）

范围包括桌面设置、其中的技能中心和配置保存入口。普通草稿编辑统一在“保存并应用”时提交；额外确认仅用于不可逆删除、隐私授权、发布状态变更、破坏性迁移和结果未知的请求处理。

## 取消的重复确认

| 操作 | 原交互 | 调整后 | 理由 |
| --- | --- | --- | --- |
| 技能改进方式 | 选择方式、采用此方式、保存 | 点击立即更新草稿及按钮高亮，再保存 | 可撤销的配置草稿，无需多一次采用 |
| 模型改名 | 编辑名称、确认名称、保存 | 切换模型、增删条目或保存时校验并投影名称引用 | 与其他字段使用同一保存边界 |
| 角色改名 | 编辑名称、确认名称、保存 | 切换角色、增删条目或保存时校验并投影委派引用 | 引用原子更新；非法名称仍阻止操作 |
| 撤回人工反馈 | 撤回、通用确认 | 直接撤回 | 保留历史修订和使用证据，不删除记录 |
| 撤回缺失能力报告 | 撤回、通用确认 | 直接撤回 | 保留历史修订，可重新提交 |
| 取消技能生成作业 | 取消、通用确认 | 直接取消，保留就地影响说明 | 停止未完成工作，不回滚已发布版本或已发生用量 |
| 取消学习作业 | 取消、通用确认 | 直接取消，保留就地影响说明 | 停止后续写回，不删除已保存历史或正式技能 |
| 恢复已忽略的后续建议 | 恢复、通用确认 | 直接恢复 | 不清理已有候选、不授予技能发布权限 |
| 新技能创建人工重试 | 核对条件、确认授权、通用确认 | 核对条件、确认授权 | 保留明确费用授权，删除第三次重复确认 |

技能方式点击只改内存草稿，不自动保存或请求模型。选择当前方式不改写高级配置，尤其保留“自动起草，人工审核”下额外开启的纠正、缺失报告和成功流程发现规则。切换到手动或普通自动发现时关闭经验学习链路、跨会话学习和经验自动补丁，保证选择与高亮一致；模型、来源、额度和非关闭模式的行为评测参数保留。

## 保留的必要确认

| 操作 | 保留原因 |
| --- | --- |
| 删除保存的会话历史、删除记忆 | 永久删除持久化内容 |
| 将记忆提升到全局 | 扩大数据可见和可用范围 |
| 拒绝技能提案 | 终结该候选的审核流程，不能简单切回待审 |
| 技能版本回滚 | 改变正在使用的发布版本；确认前仍重新读取当前 head |
| 允许或撤销会话学习贡献、工作区共享 | 涉及隐私授权及旧学习来源、传递派生内容的清理 |
| 开始一个新目标 | 新增不可逆的学习任务边界，服务没有幂等回执 |
| 忽略归并结果后续建议 | 取消相关匹配和未发布候选，撤销旧候选来源 |
| 人工重新裁决已有技能目标 | 取消并清理旧的未发布候选，改变后续准入依据 |
| 转换为本地便携执行器 | 改变执行隔离边界并清理不兼容设置 |
| 子代理配置、技能改进配置迁移 | 转换旧结构或 CLI 优先级；确认仍绑定被审阅的配置修订 |
| 带未保存修改重新加载或退出 | 防止无意丢弃草稿；保存退出和退出时仍在执行操作的保护保持不变 |
| 结束结果未知的学习操作状态 | 防止误判失败后重复执行非幂等操作 |

发布技能继续使用查看差异和评测后的“确认发布”，不增加通用确认。新技能人工重试仍保留核对条件后的明确授权。这些步骤决定是否执行高影响动作，不作为冗余弹窗删除。

## 不属于二次确认的交互

- “保存并应用”是配置提交入口；验证、权限契约、配置修订检查以及应用失败重试不变。
- 密钥“清除 / 取消清除”仅切换草稿意图，保存前可恢复。
- 模型、角色、MCP、技能源的普通增删改仍是草稿操作，不新增确认。
- 一般外观偏好继续即时生效；守护服务暴露配置的应用按钮是提交步骤，不是第二次确认。
- 作业请求继续沿用服务身份、会话绑定、预期状态版本、幂等键和结果核对，不以去掉弹窗为理由绕过任何条件。
