# 桌面运行状态面板

右侧的 **DeerFlow 运行状态** 面板默认展示当前会话的执行情况。对话上方的 **运行状态** 按钮可以打开它。

- **主 Agent** 展示连接、思考、生成回复、执行、等待审批或回复等状态，以及当前或最近一次工具活动。
- **Todo 进度** 展示当前轮次的计划、待执行 / 进行中 / 已完成状态，以及已完成条目占比。计划通过 ACP 实时更新；未上报计划时显示空状态。对话结束或中断不会自动完成 Todo。
- **子 Agent** 展示角色、任务描述、前台或后台模式、模型、等待原因，以及宿主已记录的模型调用、工具调用和 token 用量。运行和等待的任务排在前面；已完成记录只展示当前轮次最近一棵根任务中的子 Agent。较早轮次仍未结束的子 Agent 继续显示。

Agent 状态在连接期间、面板可见时每 5 秒刷新，收到运行时通知时也会刷新。列表会自动读取后续页，受现有缓存数量和大小限制；分页未完整加载、按根任务筛选或断开连接时会标明状态。没有上报调用用量时显示“调用进度尚未上报”。调用次数用于了解执行活动，不作为任务完成百分比。

**任务详情与管理** 保留原任务树、完整任务结果、取消、恢复、执行前审批、只读工具执行记录和产物入口。点击子 Agent 可以查看该任务详情，再通过 **返回运行状态** 回到概览。

**工具执行记录** 自 2026-10-30 起仅供查看，默认分页展示全部记录，也可筛选结果不确定的记录。错误摘要、折叠技术详情和完整记录复制仍保留。结果未知时显示“结果尚不确定”，原始错误与执行证据保持不变。人工核对表单、核对人、确认执行结果的按钮及“全部核对后才能继续”的限制已移除；读取记录不会自动打开恢复流程或重放工具。旧 `needs_reconciliation` 状态显示“已中断 · 结果尚不确定”，不计入活跃任务。

普通工具失败会把可用输出和结果的不确定性返回代理。代理自行决定调查、修正参数、重试或换用方案，直到解决问题或明确结束当前轮次，不设工具失败的固定重试次数。需要用户补充信息或确认时，代理在主对话中提问并结束当前轮次；用户在主输入框回复后，同一会话保留历史并开始新一轮执行。现有预算、权限审批、用户停止和持久化保护仍然有效，存储失败或账本未结算不会被当作普通工具失败继续执行。

会话归档和显式删除不再要求人工核对终态运行的未知工具结果，但仍要求运行与任务图已结束，没有活动执行、待结算预算或其他持久阻塞。归档保留历史和证据，显式删除仍是真实删除。分支和回退继续使用更严格的历史校验，存在 `pending`、`started` 或 `uncertain` 回执时仍可能被拒绝。

Todo 按当前对话轮次展示。重新打开历史会话会恢复该轮已保存的计划，新一轮任务不会沿用上一轮的 Todo。根任务 token 用量包含后代，与子 Agent 的自身用量不能累加。

## 本地连接诊断

便携版将本机 WebSocket 的诊断写入 `user-data/logs`。按弹窗或操作发生的时间找到 `deerflow-desktop-connection-*.jsonl` 中的 `connection_closed`，再用同一个 `connection_id` 在 `waku-daemon-connection-*.jsonl` 查找服务端记录。时间使用 UTC。两端可能看到不同现象，例如服务端写入超时后，桌面只能观察到连接关闭。

`recovered` 记录新连接 ID、重试次数、耗时和 daemon PID。会话日志还记录重新挂接的结果。每个进程独立写文件，单个文件达到 2 MiB 后轮转，保留最近两份轮转文件。日志字段包含错误类别、可用的操作系统错误码和 WebSocket 关闭码，消息正文和凭据不参与记录。
