# 桌面技能学习：阻塞诊断与恢复

## 修复的故障

同一聊天通常复用一个学习 episode。原队列、作业领取、归并和匹配将整个 episode 中所有任务都结束作为前提，较早的 `waiting_input` / `needs_reconciliation` 因而阻塞后续已经完成的独立执行树。部分来源在 SQL 过滤时就被排除，没有写入等待原因。

现在按每个来源的执行树筛选并固定快照。旧的未完成来源会被隔离，后续安全来源可以继续；同一来源中尚未结束的子任务、未核对回执和未结算预算仍会阻止该来源进入学习。混合批次中的取消、超限或无效来源只影响自身，批次总大小超限时分批处理。

最新输入还在运行时，当前 episode 的付费学习仍会暂缓，避免一边追加纠正一边提取。后续输入完成后会自动重查。没有改变原任务状态、回放工具、建立虚假的独立 episode，或降低自动发布所需的独立证据门槛。

## 桌面入口

设置 → 技能 → 进化记录：默认显示学习流水线，进入时自动读取学习、发现、生成和自动采用状态。当前聊天已有原生会话时，还会读取贡献授权和诊断明细。

- “后台在线”表示执行器可工作，不表示已经提取经验或生成技能。
- “待处理 / 已入队 / 可调度 / 阻塞 / 跳过 / 失败”分别显示。作业数量与输入数量分开计数。
- 等待与失败会展示原因；自动采用会展示缺少可信评测、没有可用目标等 readiness 原因。
- “打开原任务核对 / 恢复”定位原执行树；“核对待确认回执”进入已有的回执核对流程。导航本身不会恢复任务、确认回执或重放工具。
- 可安全重试的失败提取显示“重试原经验提取”。超时、耗尽尝试、来源变更或已有结果的任务会解释为何不可重试。
- “开始一个新目标”用于真正独立的新任务，不是解锁旧输入的手段，也不会回填历史。

页面是最近查询的状态快照，可以使用“刷新学习流水线”重新读取。

首次进入或聊天授权版本变化时，先刷新授权，再读取发现、生成与发布历史，避免授权缓存失效把刚加载的状态清空。设置页支持 Tab / Shift+Tab 遍历控件、Enter / Space 激活；聊天和终端的快捷键不受该绑定影响。

## 管理接口

`skill.learning.status` 保留原字段，增加 `running` 和 `queue`。

`queue.ready + queue.blocked = queue.pending`；`queued` 单独统计。`ready` 只表示满足调度条件，最终提取还要校验来源大小与完整性。`failed_jobs` 是作业数；`capture_limited_sessions` 是达到每聊天 128 条未处理捕获上限的会话数。原因计数可包含已入队输入的等待状态及已跳过输入的原因。

```json
{"operation":"skill.learning.diagnostics","session_id":"<native session>","limit":50}
```

返回会话、授权版本、队列计数，以及有界的输入 / 作业元数据。输入与作业各最多 `limit` 条（1–100）；超出时 `truncated=true`。不返回原始提示、工具输出或凭据。原因根据当前状态重新计算，旧记录的空 reason 不会隐藏正在发生的等待。

```json
{"operation":"skill.learning.extraction.retry","session_id":"<native session>","job_id":"<job>","expected_epoch":1,"expected_state_version":3}
```

重试仅用于允许恢复的失败提取。服务在同一事务中核对会话归属、授权、作业版本和完整快照，并检查队列及预算。原作业的尝试次数、期限、策略和账单保留；重试不会生成新的预算身份。桌面遇到响应丢失时先读取状态，不自动重复发送。

## 常见原因

| 原因 | 含义与处理 |
| --- | --- |
| `idle_window` | 未达到配置的空闲时间，等待自动调度。 |
| `source_active` | 最新输入仍活跃；等待结束，异常时定位原任务。 |
| `waiting_input` | 原任务等待输入或审批；打开原任务查看需要补充的内容。 |
| `needs_reconciliation` | 原任务执行结果待核对；通过原任务或回执入口检查实际结果，不自动重放工具。 |
| `tree_unsettled` | 该来源的执行树、回执或预算未结算；核对原任务及后代。 |
| `extraction_active` / `extracting` / `awaiting_worker` / `retry_backoff` | 原来源正在提取、等待执行器或等待自动重试。 |
| `queue_backpressure` / `budget_exhausted` | 队列或额度不足；等待释放或按 UTC 日重置，并核对实际配置。 |
| `unsafe_outcome` | 取消或效果不确定的结果不能直接成为学习样本。 |
| `source_bounds` | 保存的来源超过有界提取限制；原任务仍保留。 |
| `source_invalid` | 保存的来源或回执完整性校验不一致，不应当作可信样本。 |
| `evidence_blocked` | 模式证据未解决、有冲突或歧义，不能据此匹配或发布。 |
| `deadline_expired` / `attempts_exhausted` | 失败作业的原期限或次数已用尽，不能通过重新排队绕过。 |

## 验证范围

回归覆盖旧未完成任务隔离、同根后代阻塞、混合不安全来源、跨批次与重启恢复、快照完整性、撤回授权、有限重试、未知响应与陈旧界面条件。

原生端到端测试使用隔离目录和本地确定性模型服务：真实用户执行、空闲触发、经验提取、归并、匹配、自动发现、生成、评测、受限发布，以及重启后读取新技能版本。分别验证旧 `waiting_input` 和 `needs_reconciliation` 的场景。配置落盘测试还验证新技能即使在自动模式下也需要人工审核。无需真实供应商调用。

现有数据只能在 SQLite 一致性副本上做入队排查；空提取适配器验证队列与来源检查，不代表历史内容已成功生成经验。生产数据库和运行中的任务不应作为测试夹具。
