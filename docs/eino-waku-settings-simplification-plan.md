# Waku 设置界面简化方案

日期：2026-10-04。基于 `codex/eino-harness-acp-refactor`，实现基线 `cd2fd510`。

用户确认方案后已实施。第一版使用统一的配置草稿，设置分为常用、模型、工具与权限、高级、外观五页；技能中心独立进入。以下保留设计依据，并在文末记录实施和验证范围。

## 1. 当前问题

当前实际可见的外层设置入口为 DeerFlow、通用、外观；DeerFlow 内部再分为概览、模型、子代理、长期记忆、技能、工具与权限、ACP 运行，共 7 个分页。

- 技能页连续展示来源、进化设置、技能目录、反馈、缺失报告、发现、生成、自动补丁观察、旧历史、提案审查等 10 个模块，再追加大量参数表单。
- 多个页面先展示整块“当前运行值”，随后展示草稿，用户需要反复比较两处内容。
- 顶部同时提供保存并应用、校验、重新加载等按钮；服务控制和运行状态也占据较大区域。
- 高级展开目前主要用于 ACP 运行页的少量字段，技能及角色的专业参数仍集中出现。
- 工具参数条目的添加、移除与工具能否执行含义不同，当前需要阅读较长说明才能区分。

目标：常用页默认可编辑项控制在 8 个以内；日常任务最多经过两次导航即可找到；高级能力和已保存配置完整保留。

## 2. 推荐结构

统一为单层设置导航，取消 DeerFlow 内部横向 7 分页。全局设置保留以下 5 个入口：

| 页面 | 默认展示 | 深入入口 |
| --- | --- | --- |
| 常用 | 默认聊天模型、子代理开关及并发数、长期记忆开关、技能开关、技能改进方式 | 子代理角色管理、记忆管理、技能中心、维护预算详情 |
| 模型 | 模型列表、默认标记、添加和编辑 | 所选模型的更多参数 |
| 工具与权限 | 工具审批方式、命令执行位置、网页搜索/抓取、OpenCLI、MCP 接入入口 | 单工具参数、细粒度允许/拒绝列表、MCP 权限详情 |
| 高级 | 子代理、记忆、技能维护、运行与数据等折叠分组 | 展开对应参数；服务状态与诊断；旧数据导入 |
| 外观 | 当前主题、字号等显示设置 | 现有本地显示选项；将通用页的数学公式显示项并入此页 |

另在工作台增加独立“技能中心”入口，承载技能操作，避免技能管理与设置长表单挤在同一页。

此处的“命令执行位置”展示当前实际 provider 与授权；只提供现有后端明确支持的选择，不把 Windows/WSL/Docker 假设为等价环境，不通过切换选项静默扩大本机权限。

## 3. 各页交互

### 3.1 常用

默认只有 7 项：默认模型、允许子代理、子代理并发数、长期记忆、加载技能、技能改进方式、每日维护模型调用上限。

- 子代理关闭时隐藏并发输入，已保存值保留；角色列表通过“管理角色”进入。
- 技能改进关闭时隐藏每日维护额度，已保存预算保留。
- 默认模型的选择只在本页编辑。模型页展示默认标记和跳转入口；高级中的会话模型覆盖明确标为“覆盖默认模型”。
- 服务状态缩为一行：运行正常、等待生效、需要处理等；异常时出现具体修复入口。
- 维护额度旁保留“可能产生模型费用”的简短说明，上限与剩余额度分别标识，不估算没有价格依据的金额。

技能改进方式可提供三种常见选择：

| 选择 | 含义 |
| --- | --- |
| 关闭 | 停止新的维护工作，历史和已配置参数保留 |
| 手动改进，审核发布 | 保留手动提交/生成与审查，新版本经人工批准发布 |
| 自动发现，审核发布 | 根据明确纠正、缺失报告和重复成功流程生成候选，发布仍需人工批准 |

选择会明确展示拟修改的相关开关及必要条件，不用简单总开关掩盖生成、发现、发布的不同含义。三类发现可以在详情中分别控制；当前文件若是其他有效组合，显示“自定义”，直到用户主动选择方式才转换。受限自动补丁留在高级设置，继续要求可信行为套件与现有安全条件。

### 3.2 模型

- 使用模型列表，每行显示名称、提供商、模型 ID 与默认标记。
- 点击一行才显示该模型的编辑区域，基础字段保留显示名称、提供商、模型 ID、API 地址和密钥。
- 配置引用名、描述、上下文窗口和图片输入能力放入“更多参数”。引用名变更继续原子更新相关引用。
- 密钥显示“已配置”并支持输入新值；清除密钥作为明确操作，不再长期占据一个开关。
- “测试连接”只属于当前模型，仍明确说明会发送真实请求，不自动测试全部模型。

### 3.3 工具与权限

- 按网页、文件、命令、OpenCLI、MCP 分组显示列表；点击具体工具才编辑参数。
- 参数条目显示“已配置/使用默认参数”，执行权限另显示“允许/受限制/未知”，不将移除参数条目设计为禁用工具。
- 超时、返回条数、代理、站点限制等进入该工具的详情或高级折叠区。
- 命令能力区解释必要授权组合，展示分别控制的开关；不将多个独立权限压缩成会扩大授权的模糊开关。
- MCP 用服务器列表与添加表单展示，保留现有 stdio 范围。宿主可执行文件授权、环境变量保密和客户端接入权限仍独立校验。
- 常用表单不展示整段 JSON；原始参数查看与复制放入高级详情。密钥及环境变量值沿用当前保留、更新和脱敏规则。

### 3.4 高级

以下分组默认折叠，标题显示简短当前状态：

1. 子代理：超时、轮数、层级、后台槽数、任务上限、自动续跑；角色采用列表和单角色详情。
2. 记忆：注入、检索、接入模式和作用域；浏览、删除记忆通过管理入口。
3. 技能维护：三路模型、发现规则、Token/作业预算、生成与审查限制、行为评测、受限自动补丁。
4. 工具权限：精确允许/拒绝列表、MCP 宿主授权与受支持的接入配置。
5. 运行与数据：并发、连接数、排队/运行超时、会话保留、附加指令、目录信息。
6. 服务与诊断：当前运行值及来源、日志路径、启动/停止/重试、重新读取配置。
7. 旧数据导入：旧角色预览和只读进化历史导入。

必须开启的安全审查规则显示为只读状态；其完整说明可展开。错误涉及隐藏字段时，自动展开对应分组并定位字段。

## 4. 技能中心

设置只负责开关和规则，技能中心提供操作列表：

| 入口 | 内容 |
| --- | --- |
| 我的技能 | 搜索、启停、内容、来源、版本及导出 |
| 待审核 | 候选列表、差异、安全/质量/行为报告、批准和拒绝 |
| 生成记录 | 手动生成、自动发现记录、作业状态、失败原因和详情 |
| 发布历史 | 已发布修订、自动补丁观察、回滚和旧只读归档 |

- 首屏只展示所选列表；证据、回执、差异和评测详情按选择读取，保留现有分页及有界缓存。
- 待审核入口显示数量提示；不自动批准或重新执行工具。
- 与当前会话有关的纠正反馈、缺失报告优先通过会话入口提交，并携带真实 ACP 会话身份；技能中心保留当前会话入口和状态说明。
- 技能源和维护规则通过“管理来源”“维护设置”跳转，不嵌入完整参数表单。
- 配置草稿与技能操作保持既有约束；需要已应用配置的操作会解释原因，不自动保存或丢弃草稿。
- 工具回执核对仍使用已有“任务与工具核对”入口，避免与技能审核混淆。

## 5. 保存、搜索和状态

### 保存

- 对 Go 配置使用固定底部操作栏：一个主按钮“保存更改”，次按钮“撤销更改”。只有存在修改时显示。
- 主按钮复用当前校验、保存及应用流程，保留独立结果：已保存并生效、已保存等待空闲、应用失败可重试。
- 不强制中断正在执行的会话；现有任务保持原快照。
- 校验错误显示在字段旁，页面汇总错误数；必要时跳转、展开并聚焦。
- 原“校验”“重新加载”进入更多操作菜单；有草稿时重新读取仍需明确处理草稿。
- 外观类本地偏好沿用即时生效，并与 Go 配置保存范围明确区分。

### 搜索

沿用现有设置搜索入口，将搜索范围从页面名称扩展到字段标题、说明及别名，例如“代理”“OpenCLI”“并发”“预算”。选择结果直接定位字段并展开其分组；输入值、密钥和用户内容不进入搜索索引。

### 当前运行值

默认不在每页复制完整运行值表。字段草稿与已知运行值不一致时显示“尚未生效”；完整运行值及 YAML/CLI/default 来源集中在高级诊断中。不具备服务证据时显示未知，不用草稿冒充运行值。

## 6. 实施方式

### 第一阶段：导航与表单分层

- 调整 `SettingsPage` 和导航，合并通用显示项，取消旧的 7 分页入口。
- 增加静态展示元数据：页面、分组、基础/高级级别、搜索关键词和依赖条件。该层只决定显示方式，不复制或替代 Go schema 的校验规则。
- 常用字段绑定现有 draft 路径；全应用继续使用一个配置草稿和现有字段错误模型。
- 重排模型、工具、角色为列表和所选项详情；加入高级折叠与统一底部保存状态。
- 带草稿切页、折叠或切换所选项时不丢失输入；隐藏项仍参与完整配置校验和保留。

### 第二阶段：技能中心与搜索

- 将当前技能目录、生成、发现、评测、提案、发布及导入模块接入独立技能中心路由。
- 复用现有管理请求、能力检测、幂等键、版本 CAS、连接代际和分页机制。
- 将字段搜索与错误定位接到统一页面/分组元数据；MCP 原生添加表单复用当前配置消费路径。

上述两阶段构成第一版交付。第一版沿用当前主题和控件；不增加配置预设、新的后端、Python、HTTP 接口或未经实现的选项。

核心涉及文件为 `desktop-app/src/app/settings.rs`、`app.rs`、`deerflow_settings.rs` 及其既有模型/工具/角色/技能模块。Go 配置工具原则上维持现有语义；确需补充展示能力时，仅扩充对应描述，不迁移既有 YAML 结构。

## 7. 配置兼容与验收

兼容要求：

- 打开界面、切换页面和展开分组都不写配置；高级字段折叠不改变其值。
- 保留当前 7 个模型、13 个工具、密钥、OpenCLI、代理、子代理角色、技能源及维护预算。
- 保持稀疏覆盖、`null` 继承、空列表与禁用的不同语义，来源/版本变化继续按现有规则处理。
- 不因界面简化开启付费模型请求、自动发布或扩大工具权限；用户主动选择相关方式时才变更。
- render 只访问缓存；文件、进程、网络和服务请求继续在后台执行。页面搜索和列表查询使用有界结果，旧响应不得覆盖新目标。
- 控件可通过键盘操作，折叠分组和详情保持合理焦点，状态不只依赖颜色。

验收仅覆盖此次界面重排的具体风险，不扩大规模：

1. 一次定向 Rust 编译检查；复用必要的既有保存/字段契约用例，不跑全量或 race。
2. 有修改时跨页面、折叠和返回保持草稿；保存错误可定位隐藏字段。
3. 无关保存保留高级值、继承状态、密钥和权限；不产生额外收费调用。
4. 当前模型可编辑并保存，运行配置状态准确；技能中心能完成已有列表查看和审查流程。
5. 当前配置升级后正常加载，常用页默认不超过 8 个可编辑项。

验证范围限定为定向 Rust 编译及两个设置用例；原生界面的实际操作和视觉效果仍需使用新程序确认。

## 9. 第一版实施记录

- 设置导航已改为五页，常用页最多七个可编辑项，通用数学显示设置移入外观。
- 模型、工具和角色采用列表及所选项详情；更多模型和工具参数折叠，密钥清除改为保存前可取消的按钮操作。
- 高级分为子代理与角色、记忆、技能维护、技能来源、运行与数据、服务与诊断、旧数据导入。精确工具权限保留在工具页的更多参数中；技能维护再分七个折叠组。
- 工作台和命令面板增加技能中心，提供我的技能、待审核、生成记录、发布历史；目录名称查询沿用后端精确匹配，待审核数量仅标识本页结果。
- 单一底部保存栏复用原校验、保存和应用流程；撤销恢复已保存草稿。无效文本也按字段路径保留，切页不会丢失。
- 字段搜索索引在重新绑定时构建，覆盖标题、说明和别名，不收录输入值；最多展示十条结果。搜索及服务字段错误可展开和定位相应表单。
- MCP 新增服务器、参数和脱敏环境变量原生表单；原始 JSON 仍在更多参数中。宿主允许列表和凭据恢复规则保持现有语义。
- 技能改进方式先展示变更说明，用户主动采用后才更改草稿；自定义组合、模型、来源、预算、行为规则和历史继续保留。

本次仅修改桌面设置展示与交互及本地化，Go harness、协议、配置 schema、模型请求和工具执行逻辑均沿用基线。

验证记录：定向编译及 `settings_search_filters_pages_for_arrow_cycling`、`settings_mode_changes_preserve_limits_models_and_custom_discovery` 两个用例通过。未运行全量测试、race、模型请求矩阵或视觉自动化。

交付采用本分支干净提交的 Release 构建，保留匹配的二进制 ZIP、源码 ZIP 和 `BUILD_SOURCE.json`。归档须在个人数据迁入前生成；迁移时核对数据库与配置哈希，技能维护继续采用当前的审核发布配置。具体提交身份与归档检查结果以新包和构建记录为准；本文不替代原生界面实际操作验收。
