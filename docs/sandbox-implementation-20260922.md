# 沙箱适配实现记录（2026-09-22）

依据 [沙箱专项评估](sandbox-upstream-review-20260922.md) 独立实现，保留本项目 Local、WSL 与 Docker CLI 架构，没有合并上游代码或增加新的云沙箱 provider。

## 执行结果与验收

命令执行器提供 `CommandResult`，保留正文、退出码、`completed/timed_out/cancelled/unknown` 状态以及终止确认。原有 `execute_command()` 仍返回可读文本，新增 `execute_command_result()` 提供完整结果。

bash 工具把执行证据写入 `ToolMessage.artifact.sandbox_command`，与输出裁剪分开存储。证据绑定原始命令；子任务的 `tests_passed` 验收同时要求工具成功、证据版本匹配、命令一致、正常完成、整数退出码为 0、终止已确认及有效测试摘要。只有 stdout 中的 `passed`、旧历史中的文本结果或第三方 provider 无法确认的结果，都不能单独通过验收。

## 超时与取消

`sandbox.bash_command_timeout` 扩展为三类 provider 共用的有限正数期限，默认 600 秒，支持小数。无需修改现有有效配置。

异步 bash 工具使用独立取消信号，在取消后等待自身命令清理，反复取消也不会把清理任务遗弃。Local 使用受控进程执行器；WSL 和 AIO 在 Linux 执行环境内使用 `python3` 监督单个命令，宿主请求期限与命令期限分开处理。停止当前命令不会终止整套 WSL 发行版或共享容器。

完整聊天链路的取消也纳入适配：原先取消若落在事件发布或 ACP 消费阶段，处于 yield 暂停状态的异步流可能迟于会话状态释放才关闭。客户端、API 和 ACP 的消费边界现在显式拥有流的生命周期，在同一持续任务内推进与关闭迭代器，并等待清理后再释放上层持有。重复取消只向执行任务转发一次，不打断已经开始的收尾。

宿主输出捕获有容量上限。后台子进程仍持有输出管道时，宿主只进行有限等待并返回未确认状态，避免主线程关闭管道时无限阻塞。Windows Local 仍使用 `taskkill /T` 清理可识别进程树；没有增加 JobObject，不能保证追踪已经脱离、并完全重定向标准 IO 的后台进程。

远端执行只有收到本次监督器的最终回执才确认终态。丢失连接或无法确认收尾时报告 `unknown`，不重放原命令。AIO 会保留终止未知资源的占用，后续只有观察到容器已经停止或不存在才允许回收该占用。

WSL 发行版和 AIO 镜像需具备 Python 3.9+（`python3` 命令）与 `/proc`。监督器使用 Linux subreaper 追踪脱离原进程组的子孙，并以 pidfd 确认目标身份；缺少相应内核能力或无法完成清理时返回 `unknown`。该实现不依赖上游 HTTP SDK 的 `hard_timeout` 接口。

## AIO 命令与资源生命周期

用户命令执行前单独选择 shell，用户命令返回 126/127 后不再换 shell 重跑。容器内命令和文件操作登记占用；文件操作的超时、通信异常或明确的 Docker 断线诊断也会保留未知状态并阻止写入 fallback 重放。运行中或终止未知的资源不参与容量淘汰。容量全部繁忙时返回明确错误，调用方可以稍后重试。

容器执行、检查和删除使用不可变 Docker ID，创建代际带唯一名称和 owner label，防止旧对象操作后来的同名资源。创建请求超时或返回内容不确定时保留待确认记录与容量，通过观察性检查恢复追踪；明确失败且确认无资源后才释放。删除失败也保留记录，确认资源不存在后再释放容量。

复用前检查资源是否仍然运行。全局 provider 初始化受锁保护，避免冷启动并发生成多个管理者。空闲回收保持机会式机制，在下一次 acquire 检查；没有新增后台定时清理线程。

## 搜索与文件读取

Local、WSL 与 AIO 共用文件搜索算法，AIO 通过单独 JSON 参数在容器内运行同一份算法。搜索恰好达到上限时仍算完整，观察到额外匹配才标截断；保留既有结果上限、忽略目录和只读映射。

搜索覆盖信息说明已搜索文件数、跳过的大文件、二进制文件、超长行与链接。权限、根路径不存在和非法正则保留各自错误语义；读取失败不能当作完整的无匹配结果。工具在覆盖不完整时显示说明。

`read_file` 默认通过 provider 有界读取，优先保留完整行；超长单行按 UTF-8 边界分片，CRLF 不跨片拆开。既有行范围仍可使用。新增参数：

- `max_bytes`：每次读取源文件字节上限，4 至 1,048,576；工具显示预算可能进一步降低它。
- `offset`：前一片给出的源文件字节位置。
- `expected_version`：前一片的文件版本。非零 offset 必须携带，且续读时省略 start_line；有 end_line 的选择可继续传递该终点。

工具保留可读续读提示，并在 `file_read` artifact 中提供字节位置和版本等信息。显示沿用换行规范化；Local/WSL 对 Agent 写入的文件保留虚拟路径显示，路径前缀跨片时也不会重复或遗漏，用户上传内容保持原样。源内容与显示内容分开，位置始终按源字节计算，读取后仍可使用既有字符串替换工具编辑。版本检查使用文件身份、大小与修改时间，是乐观变化检测，不承诺事务性文件系统快照。检测到变化时要求重新开始。

`ls` 新增 `max_entries`（1 至 1000，默认 200）与 `cursor`。目录分页只保留一页候选，扫描期间验证目录版本；显示预算不足时缩小页大小，不丢弃已消费但未显示的条目。目录变化后拒绝旧游标。旧第三方 provider 可以继续使用原有文件接口，但不能声称支持新的有界读取和分页。

新的字节窗口参与循环检测，正常续读不会被误当成重复调用；相同窗口的重复调用仍受到约束。

## 验证

针对性回归覆盖真实工具包装和验收、反复取消期间的清理所有权、各 provider 的超时参数、AIO 不重放、活跃占用与创建/删除不确定态，以及跨 provider 的搜索、UTF-8/CRLF 续读和变更检测。

最终验证结果：

- 全量执行 `.venv/Scripts/python.exe -m pytest -q --tb=short`：**1565 passed、14 skipped、15 subtests passed**，耗时 210 秒；仅有一条第三方飞书 SDK 的弃用警告。
- 沙箱、工具层与验收专项：**291 passed、8 skipped**。覆盖 Windows 真实进程树超时与取消、管道继承的有限等待、执行回执，以及跨 provider 文件契约。
- 聊天、客户端和 ACP 受影响回归：**180 passed、8 subtests passed**。覆盖取消落在事件发布/消费阶段、重复取消、清理异常保留、会话保护与提前结束。
- `git diff --check` 通过。专项计数与全量有重叠，不作相加。

真实 WSL 集成未执行：本机执行 `wsl -d Ubuntu-22.04 -u ubuntu -- python3 --version` 返回 `Wsl/Service/E_ACCESSDENIED`，提权检查未获执行结果。也未执行真实 Docker 容器故障注入；AIO 的生命周期故障通过 fake Docker 验证，远端文件协议则使用本机 Python 真正执行共享脚本。上述离线验收不能替代目标 WSL 发行版和容器镜像的进程树集成测试。

桌面分发兼容性已只读核对：现有打包使用 Embedded CPython，并安装保留 `.py` 的项目 wheel；新增模块和共享脚本可按现有方式打包，无仓库绝对路径依赖。本轮未重新构建发布包。
