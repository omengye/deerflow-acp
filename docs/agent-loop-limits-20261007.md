# Agent loop 停止策略

2026-10-11 补充：任务、前台排队和原生子代理累计时长也默认不限时，零值关闭对应时限。保留工具与握手超时、租约校验和手动取消。下文运行超时仅指宿主显式配置的限制，不再是默认停止条件。

本次故障记录显示单次运行恰好执行了 50 次模型调用和 50 次工具调用，触发原来写死的迭代限制。累计模型调用预算为 100 次、工具预算为 200 次，均未耗尽。ACP 的 `max_turn_requests` 是协议停止原因，本身不能区分这些限制。

默认策略调整为完成任务、用户取消或运行超时后停止。主代理的迭代限制、全任务共享的模型和工具调用次数限制均默认关闭。子代理原有的隐式 50 轮限制也关闭。保留单次模型输出上限、并发限制、权限检查、运行及工具超时和上下文压缩。

宿主可显式启用次数预算，零值关闭对应限制。

```yaml
local_acp:
  max_iterations: 0
  max_model_calls: 0
  max_tool_calls: 0
```

直接 Go 可执行程序对应 `--max-iterations`、`--max-model-calls` 和 `--max-tool-calls`，CLI 优先于 YAML。配置更改需重启 daemon。桌面保存其它设置时保留这些宿主字段。

子代理的 `subagents.max_turns` 和各角色的 `max_turns` 为可选限制，未设置或设为零时不限制。显式的父代理上限仍约束子代理，子代理不能通过零值绕过父限制。

当前 Eino SDK 把零值解释为默认 20 轮，因此只在调用 SDK 的边界把无限策略转换为最大整数计数器。对外配置和不可变执行协议仍记录零；没有将 50 换成另一个业务轮次常量。SDK 以后支持原生无限值时可替换这层适配。达到显式迭代上限会返回 `limit=iterations` 并显示可继续执行的说明，ACP 的标准停止原因保持不变。

已有暂停任务的预算与执行协议不改写。已结束任务可以在原会话发新的继续请求，使用既有工具结果和新策略。无限轮次不会解决工具本身的网络超时、脚本错误或无进展循环；这些仍需分别诊断。
