# 桌面模型信息补全

桌面模型设置可以从 models.dev 的公开目录补全 `context_window`、
`supports_vision` 和当前适配器支持的 `reasoning_efforts`。下载、缓存、匹配和
建议界面均在桌面 Rust 中实现；沿用 Go 后端已有的配置校验和保存协议。

## 使用

- 新建预设填写模型 ID、API 地址后，短暂停止输入会触发后台匹配。供应商端点
  和模型 ID 唯一匹配时，自动填入尚未手动编辑的字段。
- 已有预设点击“补全模型信息”，核对供应商和各字段的当前值、建议值，勾选后
  点击“填入选中字段”。所有修改先进入草稿，保存并应用后生效。
- 自定义网关或多个候选需要手动选择目录条目；可搜索供应商、模型名称和 ID。
  手动选择不会替换实际模型 ID、接口地址或密钥，也不持久化目录绑定。
- 新建预设改变模型 ID、接口地址或适配器时，撤回为旧身份自动填入的值。
  用户手动编辑或明确采用的字段始终保留。保存后按已有预设处理。

本期不调整 `thinking_parameter`、思考预算、最大输出或价格。只有 OpenAI
兼容适配器导入明确声明的 low、medium、high、xhigh、max 档位；Claude 以及
已经配置 `thinking_parameter=reasoning_effort` 的预设保留其原档位。
目录中的 `reasoning=true` 本身不能开启思考开关。

## 离线与失败行为

目录不是启动、聊天、编辑、保存、配置校验或应用的前置条件。只有模型补全
操作会触发目录读取，使用独立的后台任务和加载状态，不冻结设置页。

- 缓存有效期为 24 小时。过期缓存可以立即展示建议，后台尝试更新；自动填入
  只使用未过期的有效目录。离线时仍可手动采用缓存中的建议。
- HTTP 连接超时为 2 秒，总请求超时为 5 秒；失败后暂停重试 10 分钟。
  “刷新目录”跳过正常缓存有效期，但遵守失败冷却。
- 同时只下载一份目录；其他请求立即使用缓存或返回正在刷新的提示，不等待
  网络、不占用后台线程等待锁。
- 无缓存且查询失败时，模型字段保持原样，提示继续手动配置。坏 JSON、无效
  目录及超限响应不会覆盖最后有效缓存；写缓存失败时仍可使用本次内存结果。
- 缓存位于系统缓存目录下的 `DeerFlow Desktop/models-dev/catalog-v1.json`，
  不属于模型运行配置，删除后可重新下载。网络响应及缓存最多 20 MiB。
- 请求固定访问 `https://models.dev/api.json`；配置密钥、聊天内容和自定义
  模型端点不会提交给目录服务。远程服务模式仍由桌面电脑下载目录。

## 实现与验证

目录模块为 `desktop-app/src/app/deerflow_settings/models_dev.rs`；匹配和三字段
映射位于 `model_metadata_logic.rs`；独立异步状态及草稿交互位于
`model_metadata.rs`。所有目录扫描、JSON 解析、磁盘及网络操作在后台完成。
渲染只使用已经缓存的状态，候选列表分页显示。

查询结果使用独立 generation、模型身份与编辑 revision 校验。模型切换、
编辑、删除、保存、重载和用户选择建议均可使旧结果失效；更新目录时清除旧
候选及差异，防止目录已经移除模型后仍应用旧建议。

针对性测试使用本地 HTTP fixture，不调用真实模型接口：

```powershell
cargo test --locked --offline --release -p waku --lib app::deerflow_settings::model
```

覆盖精确端点匹配、未知网关、显式 false/0、档位过滤、身份变化回退、旧响应、
目录刷新移除模型、缓存、坏响应、超时、冷却、写盘失败和并发刷新。
