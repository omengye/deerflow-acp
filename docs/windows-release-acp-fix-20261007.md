# Windows ACP 启动与配置恢复修复

修复范围：已有配置引用 `../skills/evolved`、`../skills-exports`，但目录未随配置迁移时的启动失败，以及启动等待期间的配置锁定。

## 行为变化

- 配置服务在复制初始技能后，为配置声明的便携技能存储自动创建目录。自动创建范围限定为当前 `user-data/skills` 和 `user-data/skills-exports`，不创建外部自定义路径，不覆盖已有文件，不穿过符号链接。
- 不存在的技能源和导出目录保留 `not_found` 分类。配置快照显示对应字段的诊断，让自定义路径错误可以在界面修复。
- Bridge 保留新启动进程的句柄，检测启动期间的进程退出。退出后给予并发启动实例 500 毫秒发布 endpoint 的机会，随后明确返回启动失败，不再等满 120 秒。Windows 子进程继续不继承任何句柄；关闭监控句柄不会终止共享 daemon。
- 桌面区分自动启动和配置应用。自动启动期间可以编辑、读取和保存配置；保存并应用会排队，在本次启动结束后应用最新配置。实际配置应用仍受并发保护。失败状态优先显示，失败后保留草稿及保存结果。

## 防回归验证

目录测试覆盖首次运行、复制已有配置、重复初始化、保留原配置与技能内容、外部路径缺失、普通文件阻挡和链接拒绝。Bridge 测试验证退出进程能及时反馈。

发行协议 smoke 使用包内实际程序和本地模型 fixture，新增以下门禁：

1. 复制配置后补齐缺失的受管理源和导出目录，同时保留内置技能及配置字节。
2. 自定义外部路径缺失时返回字段诊断，daemon 失败后及时清除启动和应用状态。
3. 自动启动进行中仍可校验修复草稿。
4. 用延迟退出的隔离 daemon fixture 验证启动期间可以保存，启动失败后保存版本不会回滚。
5. 修复配置后，继续执行普通会话、模型路由、审批、保存应用和会话恢复的原有验收。

这组 smoke 已接入 `scripts/build-windows.ps1` 调用的既有流程，普通及旧 MCP 策略两种模式均须通过才能归档。Windows 工作流另外运行桌面配置状态测试。未来相同类型的回归会阻止构建交付。

实际测试数量和结果记录在包内构建清单。协议与状态测试不等同于实际 GUI、线上模型或另一台干净 Windows 环境的验收，也不构成所有未来故障都不会发生的保证。

## 使用

完整解压新的 ZIP。在关闭旧程序并备份数据后，可以把原 `user-data` 复制到新发行目录，再运行 `deerflow-desktop.exe`。初始技能目录和导出目录会按上述规则自动初始化。外部自定义路径若不存在，请在技能源设置中修改路径或禁用技能，再保存应用。

旧发行目录的两个缺失目录已补齐，其个人配置字节未改动。更新二进制后才能获得上述长期修复。
