# 桌面版本 P1 最终实施方案

日期：2026-10-29（Asia/Shanghai）。源码基线：`3a2b3583`。

本轮实施覆盖五项：MCP 审批分类、会话归档与主动删除、会话分叉与回退、运行中纠偏、任务预算及费用代码清理。目标是在现有 GPUI、Waku daemon、ACP Bridge、Go/Eino 架构上补齐执行与数据生命周期，继续以 Go daemon 作为执行状态的权威来源。

正文保留已确认的实施范围与验收要求，文末记录本轮实际实现及验证结果。原第 6 项“升级与备份恢复”不纳入本轮；不新增升级器、备份恢复页面或发行管理系统。现有构建和协议检查继续作为变更验证手段。

## 一 已确认的实施范围

| 编号 | 优先级 | 实施内容 | 用户可感知结果 |
| --- | --- | --- | --- |
| 1 | P1 | 修复 MCP 工具审批分类 | 服务名、工具显示名不再改变审批结果 |
| 2 | P1 | 过期会话后台归档及缓存清理，接通主动删除 | 历史可继续；主动删除真正清除前后端会话 |
| 3 | P1 | DeerFlow 按轮次分叉与回退 | 可以从历史轮次探索新方案或恢复之前状态 |
| 4 | P1 | 运行中纠偏 | 区分当前轮介入与下一轮排队，并明确是否生效 |
| 5 | P1 | 任务预算与用量控制，删除费用及账单代码 | 显示 Token 和执行额度，不计算或展示金额 |

第 2 项的“不在界面上展示”指后台归档和缓存清理的维护设置、维护状态、通知及管理页面；不取消原有历史会话访问能力。归档标记不作为桌面列表的隐藏条件，不新增归档标签页。

第 5 项删除金额估算和供应商账单相关功能代码，保留 Token、上下文占用、调用次数和预算执行。供应商限流及额度重置状态按运行控制需要保留，不把账户限流误当作账单删除。

## 二 现状与跨层约束

当前主要调用链为：

```text
GPUI 桌面
  → 认证 WebSocket → Waku daemon（会话展示、持久消息、工作区服务）
  → ACP stdio → Rust Bridge
  → 认证本地 IPC → Go daemon / Eino（模型历史、执行、任务、回执、预算）
```

已有 worktree、diff、Git checkpoint、共享预算、持久执行、工具效果核对和子代理能力继续复用。以下约束适用于所有五项：

- Waku 的会话 UUID 与 Go 的 provider session ID 必须通过宿主持有的映射关联，不能混用或接受模型提供的任意 ID。
- 新能力通过协议能力协商开放；后端未支持时客户端明确禁用，不能仅修改 Provider 名称对应的 UI 开关。
- 状态修改携带目标身份、期望版本和幂等标识；重连、重复点击及旧响应不得误操作其他会话。
- 多进程和数据库、文件系统之间不宣称存在一个原子事务；跨层流程保存可重试的操作状态，失败后能判断已完成步骤。
- 业务历史与执行证据持久保留，缓存可以重建。恢复、归档、分叉和回退均不自动重放工具副作用。
- 渲染仅读取内存快照。数据库、文件清理、协议请求及 Git 操作在后台执行。

## 三 MCP 审批分类修复

当前 `PermissionModeDangerous.RequiresPermission` 依据名称子串判断只读，且 `read/view/list_file` 早于 `delete/write`；MCP 暴露名又包含服务名，导致如 `reader/delete_record` 的副作用工具可能免审批。

实施内容：

1. 为工具保留宿主可信的来源和稳定身份，明确区分原生内置工具与外部 MCP 工具。外部工具不能通过重名冒充内置只读工具。
2. 内置只读工具采用精确身份白名单。外部工具在 Ask 策略下默认进入审批，宿主可为精确的服务和工具配置显式授权。
3. MCP annotations 和描述可以辅助解释，不单独作为免审批依据。服务重命名、显示名调整不能扩张已有授权。
4. 工具准备、中间件、前后台子代理和恢复执行使用同一分类结果。Plan、只读模式、宿主 denylist 继续构成上限；明确选择的全权限模式保持其既定语义。
5. 执行契约纳入策略身份。旧等待执行在新规则下恢复时重新验证，不静默沿用来源不明或已失效的免审批结果。

## 四 后台归档 缓存清理与主动删除

### 4.1 自动归档

默认保留现有 5 天不活跃或关闭期限，以及启动扫描、每小时巡检的调度方式；到期动作由永久删除改为归档。已有自定义天数继续使用，原本明确关闭维护的配置保持关闭。

新增持久归档标记及必要版本信息，归档是存储生命周期状态，不等同于任务完成、取消或会话删除。扫描继续采用有界分页；标记和资格复查在既有重连互斥机制下完成。

归档必须保留：

| 数据 | 处理方式 |
| --- | --- |
| 会话身份、配置、用户消息和模型历史 | 保留，支持打开和继续原上下文 |
| 任务树、执行结果、工具回执与核对证据 | 保留，维持原有状态及约束 |
| 原始附件、生成产物、仍被引用的技能版本 | 保留，维持引用完整性 |
| 继续执行所需 checkpoint 与预算账本 | 保留，不释放仍有效的任务资源 |
| 可重建的缓存、无持久引用的临时副本 | 经清单和引用核验后清理 |

运行中、已排队、等待审批、等待依赖或存在未决副作用的会话及其相关任务图，继续受维护保护。归档扫描不得通过强制取消来获得清理资格。

再次打开归档会话时，后端在接入新执行前取消归档标记、刷新访问状态并按需加载缓存。打开操作不启动模型或恢复旧工具执行；继续任务仍遵循原有执行与回执核验。

### 4.2 缓存清理边界

实施前建立缓存清单，为每一类记录所属路径或表、引用来源、重建方式和并发保护。只有能证明是派生数据且当前未被使用的条目才能纳入。首次实现至少接通一种已确认可重建的实际会话缓存，并用验收证明空间或驻留资源被释放，不能仅新增归档字段便宣告完成。

禁止通过删除整个会话目录实现缓存清理。原始附件、生成产物、事件历史、工具回执、有效 checkpoint 以及预算记录均不属于可自动删除缓存。被其他会话、分叉或任务引用的内容不能随单个会话清理。

清理在后台分批执行，支持重复执行和中断后继续。缓存清理失败不破坏已完成的归档标记及业务数据，也不阻塞用户重新打开会话。维护错误写入既有诊断渠道，不新增界面状态或通知。

### 4.3 界面和配置迁移

- 移除设置里的“清理过期会话”“不活跃会话保留天数”“已关闭会话保留天数”及相关维护说明；不新增归档管理页、维护状态、弹窗或通知。
- 历史会话仍能按原有方式访问；自动归档不把会话从桌面历史列表移除。
- 归档策略由宿主配置管理，设置保存时保留未暴露的宿主字段，不能因 UI 删除字段而覆盖旧配置。
- 迁移后的所有自动入口必须走归档和缓存清理，不能遗留 SDK、独立 ACP 或 daemon 启动路径继续调用永久删除。
- 保持旧配置可读取；旧名称若暂时保留用于兼容，其行为必须明确映射为归档。API 和说明避免继续把归档结果表述为已删除会话。
- 先前已被永久删除的历史无法凭此次迁移自动恢复，不伪造恢复记录。

### 4.4 用户主动删除

当前列表删除只删除 Waku 的会话和消息行，并关闭 ACP 运行连接，没有调用 Go 已提供的 `session/delete`。本轮接通真正删除流程，保持主动删除与自动归档为两个独立操作。

目标流程：

1. Waku 根据持久 provider cursor 定位对应的 Go 会话，核验所有权与当前状态。尚未创建 Go 会话的桌面草稿可以只删除 Waku 数据。
2. 持久保存删除操作标识和目标映射，再请求 Go 删除。没有活跃 ACP 连接时，以已有授权通道建立受控连接或使用宿主删除入口，不创建替代空会话。
3. Go 使用已有删除保护和事务移除会话私有业务数据；清理独占附件与缓存，保留共享引用及跨会话资源。
4. Go 确认成功后，Waku 删除持久会话、消息、草稿及相关展示状态，再更新列表并清理会话专属 checkpoint refs。
5. Go 拒绝或结果未知时，不提前从列表移除，也不显示删除成功。查询或重试使用同一删除身份。
6. Go 已删除而 Waku 保存失败时，保留待完成记录；重启后继续清理 Waku。针对同一可信目标的后端“已不存在”可作为幂等完成结果，但不能掩盖身份错误或权限失败。

删除意图与完成标记应持久化，在操作未完成时阻止原会话重新激活。桌面状态合并、重连和其他客户端的旧快照不得重新创建已删除记录；只有已核实后端未删除并撤销删除意图后，才可恢复正常操作。删除状态不能仅保存在进程内集合中。

有活动执行、待审批任务或未核对工具结果时，保留原有删除门禁并说明原因，不在后台强制取消或绕过核对。任务关联的共享记忆、已正式发布的技能、其他会话引用资源按已有所有权规则处理，不因删除一个会话扩大清理范围。

主动删除不删除项目目录、代码文件或 worktree，也不撤销工具已经对外部系统产生的效果。会话删除是应用数据删除，不承诺安全擦除磁盘残留或清除历史备份。

- [归档调度与期限](../go-harness/internal/runtime/session_retention.go)、[启动入口](../go-harness/internal/launch/retention.go)
- [后端删除及资源清理](../go-harness/internal/runtime/session_delete.go)、[ACP 删除接口](../go-harness/internal/acp/agent/agent.go)
- [桌面列表操作](../desktop-app/src/app/sessions.rs)、[Waku 命令处理](../desktop-app/crates/waku-core/src/daemon.rs)

## 五 按轮次分叉与回退

现有 Waku 有工作区 checkpoint，但 DeerFlow 被排除在会话分叉与回退能力之外，因为 Go/ACP 缺少按轮次处理历史的方法。本轮补齐后端语义和协议，再接通已有桌面交互。

### 5.1 分叉

- 以稳定 turn ID 和宿主确认的已完成轮次边界建立快照，携带源会话、边界版本及幂等标识；不能仅依靠客户端当前可见消息数量截断。
- 新会话获得独立身份、有效模型历史和到该边界的上下文；原会话保持可继续。
- 附件及历史结果通过安全复制或引用计数复用，来源会话删除后仍能保留分叉所需内容。
- 历史审批和回执仅作为历史证据；不复制可执行授权、活跃租约、未完成工具调用或待执行队列。
- 新会话建立明确的新任务预算；来源会话已经发生的用量仍保留，不能因分叉而消失或重复计入同一任务。
- 复用已有工作区选择及 worktree 能力，明确新会话实际运行路径，不能暗中切换或覆盖源工作区。

### 5.2 回退

区分会话回退、代码回退和二者同时回退，桌面只提供后端与工作区实际支持的组合。模型历史的有效边界与展示记录一致，旧执行证据保留为历史，不再进入新的可执行上下文。

回退前核验会话空闲、关联子任务状态、未决工具回执以及工作区版本。Git 恢复需保护人工编辑和同工作区其他任务；不能直接无条件恢复整个目录并清除所有未跟踪文件。

涉及代码与会话同时回退时，先记录操作意图并保存回退前可恢复的工作区快照，再执行受版本保护的变更。若部分步骤成功，显示可判定的失败状态并支持继续完成或恢复；不能让界面宣称全部成功。该快照仅用于回退操作一致性，不扩展为原第 6 项的通用备份产品。

预算已发生用量不可因历史回退而减少。旧运行产生的延迟事件通过运行代次隔离，不能污染回退后的会话。数据库、远端服务和工作区之外的外部副作用不作为自动代码回退对象。

## 六 运行中纠偏

当前 DeerFlow `supports_steer=false`，执行中消息只会排队。本轮增加后端持久干预能力，并区分以下行为：

| 操作 | 目标 |
| --- | --- |
| 立即介入 | 在当前轮下一安全执行点加入新指令 |
| 下一轮执行 | 当前轮结束后，以新轮次处理排队消息 |
| 停止 | 取消当前执行，继续按现有规则核对可能已发生的效果 |

协议包含会话 ID、期望 run/turn ID、客户端幂等键和指令内容。后端先持久保存，再确认接收，记录 `accepted`、`applied`、`rejected` 等可查询状态，并允许重连后取回结果。

干预在下一次模型决策或工具调度安全边界应用。“立即介入”不承诺中止已开始的外部工具，也不能被实现为取消后悄悄发起新轮次。保存历史及已应用游标，确保不会重复注入。

若提交时当前轮已结束或身份不匹配，明确拒绝并保留用户输入，不能悄悄把指令投递给下一轮。等待审批时不能以干预文本替代明确授权；取消与介入发生竞争时记录最终结果。根任务干预也不能声称已改变正在独立执行的子代理，是否实际传播必须有对应状态依据。

桌面仅在后端协商支持后开放入口，显示指令是否已接收、已生效或被拒绝；下一轮队列继续沿用现有持久保存机制。

主要位置：[ACP driver](../desktop-app/crates/waku-core/src/driver/acp.rs)、[桌面运行时](../desktop-app/src/app/runtime.rs)、[输入区](../desktop-app/src/app/composer.rs)，以及 Go 的会话协调、执行持久化、Eino 模型调用边界和 ACP 接口。

验收覆盖长工具执行、模型流式输出、待审批、轮次刚结束、取消竞争、重复提交及断线重连。以本地 fixture 验证下一次模型输入实际包含新指令，并且只注入一次。

## 七 任务预算与费用代码清理

### 7.1 预算和用量

复用现有根任务与子代理共享预算机制，在桌面提供累计 Token、模型调用和工具调用限额的配置入口，并展示已用、剩余及停止原因。新任务可继承宿主默认或设置更小的额度；修改不能越过宿主上限。

保留 `0` 表示不设置该项限额的现有语义，不给已明确支持的长任务额外增加默认时限。已有执行使用创建时的预算快照，设置保存不改变正在运行的任务；暂停、重启、继续执行及干预均不得重置已发生用量。

输入、输出、缓存 Token 和上下文占用继续保留。根预算含后代，与子代理自身用量不能重复累加。后台技能维护继续使用其现有独立额度，界面明确用量归属，不并入聊天余额。

### 7.2 费用与账单代码删除

删除范围包括：

- LiteLLM 等模型价格表下载、解析、更新调度及价格缓存读取。
- 美元或其他货币换算、模型费用估算、费用占比、费用排名和缓存节省金额。
- 金额图表、账单展示、费用提示、仅为金额展示存在的页面状态和导航入口。
- 仅服务于供应商账单或消费金额的请求、鉴权封装、轮询和缓存；按实际调用链识别，不假定所有 provider usage 请求都是账单。
- 新协议输出中的金额字段、价格状态枚举，以及仅用于上述功能的翻译、依赖和测试。

## 十 工具故障恢复修订方案（2026-10-29，按用户最新要求实施）

取消强制人工核对执行事实的流程。工具失败由代理根据错误、输出、执行证据和当前目标决定重试次数、修正参数或更换方案，直到解决问题或明确说明未完成部分并结束当前轮次。结束轮次不删除、归档或永久禁用会话。

1. 删除右侧“检查并填写说明”、核对人、“确认已完成/未产生效果”和核对后才能继续的入口；保留只读工具执行记录和错误详情。
2. 工具错误作为工具结果返回代理，包含部分输出、退出状态和效果是否未知。宿主不增加固定重试次数，也不暗中重放工具；已有用户预算、权限、取消和资源约束仍有效。存储损坏、预算结算失败等控制错误不能伪装成普通工具失败。
3. 代理需要用户补充或确认信息时，在普通对话中提出具体问题，说明已有事实与缺失信息，结束本轮等待回复；用户在主聊天框回答后，原会话依据已有上下文继续。不得要求用户填写执行事实认证表单。
4. 副作用未知的历史记录保持真实。宿主标记纳入代理恢复路径的终态错误，使它不再触发全会话门禁；旧执行ID、检查点与回执防止自动重放。代理重试属于依据新证据或用户回复做出的新决策，不能把“进程退出”当作“远端没有执行”。
5. 前台、后台子任务、检查点验证与新消息入口同步改造。失败子任务的结果可以交给父代理；普通失败不要求用户解除数据库状态锁。继续保留并验证 Windows 子进程回收修复。
